# PeSafe · Рядом, когда важно

Приложение личной безопасности для Кыргызстана. Русский интерфейс, адаптивная PWA, исходные проекты Android/iPhone и приватный сервер оповещения близких.

**Статус: работающий MVP.** Датчики работают при открытом приложении. Это не валидированный детектор ДТП и не интеграция с диспетчерской 112. Фоновые нативные сервисы, голосовой ИИ-диспетчер и установочные APK/IPA пока отсутствуют.

## Быстрый запуск

Нужен Node.js 24 или новее. Для самого приложения зависимости не требуются:

```powershell
node server.js
```

Откройте **http://localhost:8080**. Если порт занят:

```powershell
$env:PORT='8081'
node server.js
```

Для телефона нужен HTTPS. Обычный `http://IP-компьютера:8080` не обеспечивает доступ к микрофону/GPS. Разворачивайте сервер за HTTPS reverse proxy; не обходите предупреждения сертификата.

## Что работает

Добавлены [сроки хранения и голосовой архив](docs/DATA-RETENTION.md): профиль на год с предупреждением за 30 дней, обычная запись на 24 часа, SOS на 30 дней, отдельное согласие на голос, скачивание аудио и WAV-сигналов. Закрытый браузер выполнит просроченную очистку при следующем открытии.

- Трёхшаговая локальная регистрация: ФИО, телефон, дата рождения, адрес, добровольная медкарта и близкий.
- Крупная SOS-кнопка → 10 секунд на отмену → экран помощи. Отмена одним нажатием, немедленная активация, подтверждение завершения.
- Учебный сценарий без реальных сообщений и звонков.
- Foreground-детекторы громкости и тряски, голосовая фраза в поддерживаемых браузерах с отдельным согласием. Это простые сигналы, не классификация ДТП.
- GPS с точностью, временем и защитой от устаревших координат; адрес проживания явно отделён от места происшествия.
- До 10 контактов, редактирование, основной контакт, проверка номера и дубликатов.
- Подготовка SMS, системный звонок 112/близкому, меню «Поделиться». Отправка SMS и звонок требуют действия пользователя.
- Telegram-автооповещение через собственный сервер: выключено по умолчанию, требует настройки и согласия. Статус API не выдаётся за прочтение.
- История, восстановление активной сессии, экспорт/удаление локальных данных и офлайн-оболочка.
- Android/iOS Capacitor-проекты с названиями и описаниями разрешений. Подробности: [мобильная сборка](docs/MOBILE.md).

## Попробовать безопасно

Заполните анкету вымышленными данными → «Проверить сценарий» → дождитесь отсчёта или нажмите «Продолжить тест» → «Завершить проверку». Учебный режим не отправляет сообщения, не запрашивает GPS и не вызывает телефонные ссылки.

## Автоматическое сообщение близким через Telegram

Gateway предназначен **для одного пользователя/семьи**. Получатели Telegram задаются на сервере и не совпадают автоматически с телефонной адресной книгой. Для массового сервиса нужна отдельная многопользовательская архитектура, описанная в PRD.

1. Скопируйте `.env.example` в `.env`.
2. Создайте случайный ключ: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Сохраните его в `DELIVERY_ACCESS_KEY`. Не отправляйте его посторонним и не коммитьте.
3. Пока оставьте `DELIVERY_DRY_RUN=true`; запустите `npm start`. В настройках приложения введите этот ключ и проверьте подключение. Сервер ответит, что реальная отправка выключена.
4. Для реальных согласованных сообщений создайте своего Telegram-бота через BotFather. Каждый получатель должен открыть чат с ботом и нажать Start. Получите Chat ID собственным административным способом через [Bot API](https://core.telegram.org/bots/api#getupdates), не публикуя токен.
5. На сервере задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS` и `DELIVERY_DRY_RUN=false`; перезапустите сервер. Только после проверки получателей снова подключите канал в приложении и включите «Автоотправка близким».

`node server.js` сам не читает `.env`; команда `npm start` включает `--env-file-if-exists=.env`. Можно также задать переменные окружения самостоятельно.

Токен бота не попадает в клиент или localStorage. Ключ подключения хранится только в памяти вкладки и после перезагрузки вводится заново. Сервер хранит минимальные квитанции в `.data/delivery.sqlite`, не текст SOS. Повтор того же ID не разошлёт дубли. При тайм-ауте статус неизвестен; автоматический повтор провайдеру не выполняется. Браузер не отправляет старые события из офлайн-очереди.

## Сборка, проверки и мобильные проекты

```powershell
npm install
npm test
npx playwright install chromium
npm run test:e2e
npm run build
npm run android
```

Для iPhone на Mac: `npm run ios`. Подписанные установочные файлы создаются в Android Studio/Xcode с вашими ключами. Упаковка не добавляет фоновое прослушивание. На текущем этапе нативные приложения требуют проверки на физических устройствах.

`dist/` содержит только публичные статические файлы, без сервера, БД и `.env`. На статическом хостинге работают локальные функции; серверное Telegram-оповещение требует gateway. Для встроенного мобильного приложения задайте HTTPS `PESAFE_API_URL` перед сборкой и разрешённые native origins на сервере: [инструкция](docs/MOBILE.md).

Медкарта в MVP хранится локально без отдельного шифрования. Активный SOS временно сохраняет текст для восстановления, включая разрешённые данные. После завершения текст убирается из активной записи; журнал не содержит координат и медкарты. Публичный production-релиз требует защищённого хранения, проверки согласий/возраста, нативных испытаний и аудита. Подробный перечень — в PRD.
