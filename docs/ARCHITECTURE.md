# Архитектура PeSafe

## Компоненты

Обновление: `retention.js` задаёт календарный срок профиля и TTL, `recordings.js` хранит Blob в IndexedDB, `privacy.js` управляет согласием/предупреждениями/архивом, `sounds.js` формирует WAV. Подробная политика — [DATA-RETENTION.md](DATA-RETENTION.md). SOS, запись и новый срок хранения проверяются отдельно; временный номер звонка не изменён.

```text
UI (app.js + style.css)
  ├── core.js: EmergencyMachine, SignalGate, валидация, шаблон SOS
  ├── storage.js: локальный профиль, контакты, журнал, активный инцидент
  ├── sensors.js: Web Audio, DeviceMotion, опциональный SpeechRecognition
  ├── navigator.geolocation / tel: / sms: / share
  └── bearer → Node gateway → Telegram Bot API
                    └── SQLite: идемпотентность и квитанции
PWA: Service Worker только для публичной оболочки
Android/iOS: Capacitor 8, те же web assets, foreground-возможности
```

Приложение написано ES-модулями без UI-фреймворка. Для запуска gateway и юнит-тестов нужен только Node 24+. `npm install` требуется для Playwright и Capacitor. Все runtime-картинки, шрифты (системные) и иконки локальные. Нет CDN и внешней аналитики.

## State machine

`EmergencyMachine` — единственный владелец статуса инцидента. Каждому соответствует UUID и неизменный `deadline`. `tick()` проверяет время, а не декрементирует счётчик. `activate`, `cancel`, `finish` проверяют исходное состояние. Эффект отправки вызывается только при переходе COUNTDOWN → ACTIVE. Повторные вызовы не меняют ACTIVE.

`test` — свойство инцидента, а не текущей страницы. Оно сохраняется после reload и проверяется клиентом и сервером. На restored ACTIVE нет автоматического повторного вызова доставки. Ключ подключения в памяти утрачен, интерфейс показывает неизвестный статус.

После завершения `state.emergency=null`. В history не копируется сообщение. В текущей версии один профиль на origin и одно основное окно: не запускать независимые SOS из нескольких вкладок. Для публичной версии необходим владелец сессии через native service/межвкладочную блокировку и общая серверная модель.

## API: приватный gateway

Публичный статический интерфейс доступен без ключа; оба API требуют `Authorization: Bearer <DELIVERY_ACCESS_KEY>`. Ключ 32+ символа, отдельный для конкретной семьи/инсталляции. SMS/телефонные контакты на клиенте не определяют Telegram Chat ID.

`GET /api/health` → `{ configured, dryRun, recipients }`. Секреты не возвращаются.

`POST /api/incidents`:

```json
{
  "id": "c0c4675c-833a-4a85-b63f-63547f65cbab",
  "message": "SOS · PeSafe…",
  "createdAt": 1794484800000,
  "test": false
}
```

Время примера иллюстративное: реальный API принимает только свежие события ±5 минут. Текст 10–3900 символов; тело до 16 КБ. До шести новых событий в минуту на текущий процесс. Ограничение процесса не является распределённым rate limiter.

Ответ: `{ state, accepted, total, unknown?, note }`. `accepted` — положительный ответ Telegram; `partial` — часть принята; `failed` — явный отказ; `unknown` — нет надёжной квитанции; `simulated` — ничего не отправлено. HTTP 202 — предыдущая операция ещё pending, повтор не отправлен. HTTP 409 — попытка использовать UUID с другим payload. Идемпотентность долговечна в SQLite; gateway не хранит текст SOS.

Однозначный повтор возможен только с тем же текстом. Поэтому текст фиксируется при активации, включая время и GPS. При ручном повторе новая дата в сообщение не подставляется. Неопределённая отправка не повторяется на уровне провайдера автоматически.

Origin сверяется с Host. Для bundled Capacitor опционально разрешаются `capacitor://localhost` и `https://localhost`. Preflight не требует Bearer, сами данные требуют. Не разрешать `*`; cookie-авторизации нет. Reverse proxy должен сохранять канонический Host и ограничивать body size, TLS и сетевую доступность.

## Хранение и отказы

Пользовательские данные остаются в localStorage. Это не защищённое медицинское хранилище: перед публичным релизом требуется замена. Ошибка записи показывается, но UI продолжает доступ к ручной помощи. После подтверждённой отправки уже нельзя гарантировать отмену внешнего эффекта. `resolved` означает закрытие локальной тревоги, не отзыв сообщений и не уведомление Telegram о завершении.

Нет серверного планировщика отсчёта и offline delivery queue. Если браузер выгружен, отсутствует автоматическая отправка. Service Worker не притворяется решением этой задачи. API не попадает в кэш.

При скрытии страницы закрываются микрофон, AudioContext и speech-recognition, снимается motion listener. Если permission prompt влияет на visibility, повторный ручной запуск может потребоваться: подтвердить поведение на телефоне. Поддержка motion в WebView и speech-recognition различается; состояния доступны/ожидание/ошибка представлены явно.

## Тестирование

`npm test`: валидация, date/deadline/cancel/restore, sensor gate, приватность payload, миграция, static allowlist, ключ, dry-run/test protection, durable idempotency, partial/unknown, origin/TTL.

`npm run test:e2e`: изолированный тестовый браузер, вымышленные данные и mock GPS. Онбординг, контакты/дубликаты/приоритет, отмена, тест, активация, восстановление, отсутствие канала, XSS-escaping, клавиатура, Service Worker офлайн и размеры 360/390/768/1440. Внешние SMS/телефонные ссылки в тестах не открываются.

Playwright использует локальный тестовый сервер 8082. На машине с уже установленным Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`, иначе `npx playwright install chromium`. Физические датчики и нативные приложения этими тестами не проверяются.

## Отделение от production

Для реального сервиса нужны account/device identity, безопасные refresh-токены, отдельные tenants и получатели, проверенные согласия, подписанные webhooks провайдеров, контролируемая очередь, мониторинг, key rotation, резервирование БД и защита backup. Текущий ключ общего семейного gateway не подходит для публичного массового размещения. Подробные продуктовые требования и release gates — в [PRD](PRD.md).
